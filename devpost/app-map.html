Freelancer Swipe — App Map

A take-home guide to where things live. Snapshot of the code at commit 2ca86cf (Oct 20, 2026). The code may drift after this.

What the app is

A browser-only web app. A client picks a skill, swipes through freelancers one card at a time, and a tick reveals contact info and saves the freelancer. Freelancers add themselves with a short form.

  • Screens (src/screens/): RoleScreen, SkillPicker, SwipeDeck, SavedList, FreelancerForm. src/App.tsx shows one at a time.
  • Logic (src/lib/): pure functions with Vitest tests. pool.ts (who matches a skill), deck.ts (skip / back / wrap), validate.ts (form rules), storage.ts (the only file touching localStorage).
  • Swipe gesture: src/hooks/useSwipe.ts, hand-written pointer events.
  • Data: 15 sample profiles in src/data/sampleFreelancers.ts. Submissions and the Saved list are in the browser's localStorage.

One action: a client ticks a freelancer

Reference route (3 stops)

A route through the real code for the action above. Search for the anchor text in your editor (Ctrl+P to open the file, Ctrl+F to find).

  1. src/hooks/useSwipe.ts → releaseDecision and fly
    When you let go of the card, releaseDecision compares the drag distance with 30% of the card width (at least 100px). Past it, fly animates the card off-screen and then calls onSwipe. The ✓ button calls fly('right') directly.
  2. src/screens/SwipeDeck.tsx → const onSwipe
    Left means skip from deck.ts. Right calls onTick(current), opens ContactReveal with that freelancer, and moves the deck on with advance.
  3. src/App.tsx → const tick, then src/lib/storage.ts → addSaved / persistSaved
    addSaved adds the id once (re-ticking changes nothing), and persistSaved writes it to localStorage["fs.saved.v1"]. If the browser refuses, the app shows a toast. On reload, loadSaved reads it back, which is why Saved survives.

A practice to reuse

Give every step an observable check, and when a check breaks, ask what the evidence says before changing code.

Each slice in devpost/checklist.md had a Verify (mechanical) line, and the agent ran real browser checks against it. After slice 3, the old swipe check timed out on the ↶ button. The evidence (the new Saved checks passing, plus a screenshot of the contact popup) showed the app was right: a tick now opens a popup that covers the deck, exactly as prd.md › Tick and Contact Reveal asks. So the check was updated, not the app.

On your next project with an agent: write the "how we'll know it works" line before each step, and when something fails, ask the agent to show the evidence that separates "the app is wrong" from "the check is out of date."

Where the other actions live
  • Pick a skill: SkillPicker.tsx → App.tsx › pickSkill → pool.ts › findBySkill (no match → toast).
  • ↶ back: SwipeDeck.tsx → deck.ts › back (only undoes skips, not ticks).
  • Freelancer sign-up: FreelancerForm.tsx › submit → validate.ts › validateFreelancer → App.tsx › addFreelancer → storage.ts › persistFreelancers (fs.freelancers.v1).
  • Saved list: SavedList.tsx resolves saved ids against the pool, newest first.
