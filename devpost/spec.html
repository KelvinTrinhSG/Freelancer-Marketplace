How this works, in plain language

A browser-only website, with no server and no database yet.

  • Sample pool: 15 pre-made profiles written into the code, so the deck is never empty.
  • localStorage (a small notebook the browser keeps for one site) holds profiles submitted on this browser, plus the client's Saved list. Both survive a restart.
  • Pool = samples + submissions on this browser. That's a conscious limit until SQL Server arrives.
  • Screens are React components, shown one at a time.
  • Swipe is hand-written with pointer events: drag, tilt, fly off.
  • Publishing: push to GitHub → GitHub Actions builds → GitHub Pages hosts a free public link.

Where it breaks and what happens

Broken image link

Purple placeholder with initials.

localStorage unavailable

Samples only, plus a "Can't save on this browser" toast.

Blank page on Pages

Prevented with base: './'. Check the live URL after the first deploy.

Video link starts a drag

The link stops pointer propagation.

Decisions

Learner: frontend + localStorage · one pool per browser · GitHub Actions → Pages · Vite + React + TS · ScratchCard style · accepted: pill role buttons, marquee footer, hand-written swipe.

Agent details (changeable): Tailwind v4, lucide, Vitest, storage keys, 30% swipe threshold, starter skills, picsum images, one free-text contact field, ↶ undoes skips only.

Learner uncertainty: none raised.
